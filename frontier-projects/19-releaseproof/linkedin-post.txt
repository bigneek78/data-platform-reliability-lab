ReleaseProof: Artifact and Test Evidence Gate

Should an illustrative release proceed when artifact digests and test records disagree?

I’m sharing a self-contained Project Phoenix prototype with working code, eight local tests, a reproducible synthetic fixture, an architecture diagram, and an animated execution trace.

The valid fixture verifies one artifact with zero findings. Eight tests exercise the positive path and failures involving hash mismatch, missing files, traversal, inconsistent counts, commit mismatch, stale or future evidence, and zero-test records. These are local checks of a synthetic record.

Engineering judgment: A matching digest does not establish a trusted builder or signer. The record is unsigned and can be forged by anyone able to edit the fixture. The example commit string is an identifier, not a verified Git object. This is not a SLSA conformance claim or a complete provenance verifier.
